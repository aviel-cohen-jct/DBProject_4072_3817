# הוראות כניסה והפעלה – ספורטקס (שלב ה)

האפליקציה היא ממשק Web מלא מעל בסיס הנתונים `fantasy_db` (PostgreSQL).
הקוד נמצא בשורש הריפו:

| חלק | מיקום | תיאור |
|---|---|---|
| Frontend | `src/` | React 19 + TypeScript + Vite, Tailwind CSS |
| Backend | `server/` | Express + `pg`: API גנרי לכל הטבלאות, שאילתות שלב ב, תוכניות שלב ד |
| שחזור DB | `db/restore.js` | משחזר את הגיבוי של שלב ד (backup4.sql) + ה-Views של שלב ג לתוך Docker |

## דרישות מוקדמות

- Docker Desktop (מריץ PostgreSQL בקונטיינר `PostgreSQL_DB`)
- Node.js 20 ומעלה
- קובץ `.env` בשורש הפרויקט (קיים בריפו) עם: `DB_USER_SECRET`, `DB_PASSWORD_SECRET`, `DB_NAME_SECRET`, `DB_HOST`, `DB_PORT`, `API_PORT`

## הפעלה בארבעה צעדים

1. הרמת בסיס הנתונים

   ```bash
   docker compose -p fantasy up -d db
   ```

   (או `docker start PostgreSQL_DB` אם הקונטיינר כבר קיים)

2. התקנת תלויות

   ```bash
   npm install
   ```

3. שחזור בסיס הנתונים למצב המלא של הפרויקט (22 טבלאות, פונקציות, פרוצדורות, טריגרים ו-Views).
   הפעולה מוחקת את `fantasy_db` ויוצרת אותו מחדש מהגיבוי `DBProject_4072_3817/שלב ד/backup4.sql`:

   ```bash
   npm run db:restore
   ```

4. הרצת האפליקציה (מריץ במקביל את Vite ואת שרת ה-API)

   ```bash
   npm run dev
   ```

   ואז לפתוח בדפדפן: **http://localhost:5173**

שרת ה-API מאזין על פורט 5001 (`/api/...`), ו-Vite מעביר אליו את הבקשות אוטומטית.

## כניסה למערכת

במסך הכניסה יש שני תפקידים:

- **סוחר** – בוחרים משתמש קיים מטבלת `USERS` ולוחצים "כניסה לבורסה".
  אפשר גם ללחוץ "משתמש חדש? הרשמה" כדי ליצור חשבון חדש (INSERT ל-USERS).
- **מנהל ליגה** – לוחצים "כניסה כמנהל ליגה". המנהל מנהל את כל נתוני הבורסה והליגה.

## מפת המסכים

### סוחר
| מסך | מה עושים בו | טבלאות / תוכניות |
|---|---|---|
| שוק השחקנים | חיפוש וסינון שחקנים, מעבר לפרופיל | PLAYERS, PRICE_HISTORY |
| פרופיל שחקן | גרף מחירים, ביצועים בעולם האמיתי, **קנייה / מכירה** | `prc_execute_trade` + טריגר `trg_transactions_validate`, View `V_BURSA_PLAYER_SCOUTING` |
| הסגל שלי | שווי, תשואה, הרכב/ספסל | USER_SQUADS (UPDATE), `fn_calculate_portfolio_value` |
| היסטוריית פעולות | כל העסקאות של המשתמש | `fn_get_user_transactions` (REF CURSOR) |
| תובנות שוק | 8 דוחות עם פילטרים | שאילתות שלב ב |
| החשבון שלי | עריכת שם, מחיקת חשבון | USERS (UPDATE / DELETE) |

### מנהל ליגה
| מסך | טבלאות (CRUD מלא) | תוכניות |
|---|---|---|
| מחזורים | ROUNDS | `prc_process_round_price_update` + טריגר `trg_players_price_history` |
| שחקני בורסה | PLAYERS ← PLAYER_MAPPING, PRICE_HISTORY | |
| משתמשים | USERS ← USER_SQUADS, TRANSACTIONS | |
| יומן עסקאות | TRANSACTIONS | |
| קבוצות ואצטדיונים | TEAM ← COACHEDBY, PLAYSFOR_PLAYER, PLAYSFOR_GK; STADIUM | |
| שחקנים ושוערים | PLAYER, GOALKEEPER | |
| מאמנים ושופטים | COACH, REFEREE | |
| משחקים | MATCH ← MATCHTEAM, MATCHSTADIUM, REFEREEAT, PLAYERMATCHSTATS, GKMATCHSTATS | |

בכל מסך ניהול: **הוספה** (המזהה מוקצה אוטומטית), **עדכון לפי מפתח** (מזינים מפתח → המערכת טוענת את הרשומה → עורכים ושומרים), **מחיקה לפי מפתח**, וכן "עריכה"/"מחיקה" ישירות משורה בטבלה.
עמודות של מפתחות זרים מציגות תמיד את השם (למשל שם השחקן) ולא את המזהה, וגם בטפסים בוחרים לפי שם דרך חיפוש.

## בעיות נפוצות

- **"Cannot connect" / מסך טעינה שלא נגמר** – ודאו שהקונטיינר רץ (`docker ps`) ושפורט 5001 פנוי.
- **הפונקציות/הפרוצדורות חסרות** – הריצו שוב `npm run db:restore`.
- **`project name must not be empty` ב-docker compose** – הוסיפו `-p fantasy` כמו בפקודה למעלה (שם התיקייה בעברית).
